# Phase 1 definition of done

Phase 1 is done when:

- architecture, hardware, firmware, backend, product, deployment, capacity, cost, risk, and roadmap documents exist and link to one authoritative source per topic, including [provider adapters](../backend/provider-adapters.md), [ADR-014](../decisions/ADR-014-aws-temporary-host.md), [ADR-015](../decisions/ADR-015-campus-final-host.md), and [ADR-016](../decisions/ADR-016-s3-compatible-storage.md);
- user-confirmed, vendor-listed, assumed, unresolved, and safety-critical facts are labeled;
- pilot, campus, and scale-target claims are clearly separated;
- all required Mermaid diagrams parse and relative Markdown links resolve;
- hardware product URLs and official references are recorded with check dates/limitations;
- power and water documents do not approve an unreviewed construction;
- no scientific thresholds, secrets, product source code, deployment code, or CI workflow implementation are added;
- obsolete architecture claims are absent, and Kafka/Kubernetes remain later phases;
- the Phase 1 checklist accurately distinguishes documentation complete from physical validation still open;
- no commit is made unless explicitly requested.

Phase 1 documentation foundation is complete. Hardware, electrical, scientific, AWS-account and campus-infrastructure sign-off remain open.

This documentation status authorizes planning handoff only. It does not authorize Phase 2 or physical battery construction.
